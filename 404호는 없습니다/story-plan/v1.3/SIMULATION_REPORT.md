# 《404호는 없습니다》 엔딩 인과관계·조건식 검증 v1.3

## 결과
- 30/30 조건식 최소 도달 증인(witness) 생성·통과
- 각 조건을 하나씩 제거한 부정 테스트 144건 통과
- 20,000개 무작위 상태 테스트: 조건 충족 엔딩 간 충돌 없음
- 40개 기존 슬롯 참조 유효, 21개 서브 엔딩 해당 사건의 실제 EV 후보와 일치
- **한계**: 합성 상태 기반 정적 시뮬레이션이며 실제 엔진에서 5야간 완주·증거 획득 UI 경로 검증은 수행하지 않음. 증거를 실제로 어떻게 verified로 전환하는지는 Claude Code 구현 테스트 필요.

## 현재 v1.2의 문제와 수정
- E07~E27은 `archive_resolution_selected = E##`만으로 엔딩 선택 가능해 인과관계가 약했음. v1.3에서 특정 장면, 연결 증거, 해당 장면의 구체적 선택, 명시적 기록 결산 확인을 요구.
- 부정 테스트를 통해 각 엔딩의 필수 조건 하나를 제거하면 불발함을 확인.
- E28·E29·E30을 상호 배타적인 최종 선택 값으로 분리. E30은 PZ01~05·핵심 EV 검증·피해자 이름 보존·외부 제출을 모두 요구.
- E01~E06은 기존 엔진 판정을 그대로 두고 테스트용 `legacy_engine_result`를 합성 입력으로 사용. **기존 엔진의 실제 조건 검증을 대체하지 않음**.

## 개발상 주의
- `evidence_acquired`와 `verified_evidence_all`은 달라야 한다. 기록을 찾는 것만으로 조작 여부를 확인한 것으로 처리 금지.
- 미검증 단서 선택/아직 도착하지 않은 조사 결과를 선제 공개하지 말 것.
- E07~E27의 서브 엔딩은 명시적인 기록 결산(별도 UI)을 누를 때만 종결; 기본 야간 종료가 서브 엔딩을 자동 선택하면 안 됨.
- story 진행 정상 루트(N2~N5)는 서브 결말을 선택하지 않아도 이어져야 한다.
- `ending_gates_30_simulated.json`은 설계 기준 데이터이며 런타임 사용 전 스키마 변환 필요.
