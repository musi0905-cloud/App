# Claude Code 가져오기 — v1.1

## 1. 신규 추가분
- `visitors_100_complete.json`: V001~V100의 방문 대사/조사 자료/판정/결과. 출입 판정은 원본 A의 safe와 다시 대조할 것. 기존 V ID를 교체하지 말 것.
- `endings_30_cutscenes.json`: 30종 컷신 4컷·대사·효과음 ID. `machine_gate`는 트리거 플래그 가설이며 **완성된 조건식이 아님**.
- `assets/backgrounds/`: 13종 SVG 블록아웃. 최종 콘셉트 아트는 따로 제작해야 함.
- `assets/actors/`: 10개 역할 × 4프레임 SVG. 사람별 최종 이미지가 아니며 발 움직임 품질 미검수.
- `assets/motion/preview.html`: 4프레임 테스트, 공식 게임 연동 없음.

## 2. 구현 순서
1) HEAD/미반영 변경/배포 상태 확인 후 백업. `dist/data/*.json` 실제 schema와 비교.
2) `visitors_100_complete.json`을 기존 visitors/anomalies와 자동 대조하여 대사의 호수/인물/Anomaly ID가 맞는지 검증. **원본 A 개별 clue 텍스트는 기존 data/anomalies.json 값 우선**, v1.1 범주형 확인 문구로 덮어쓰지 않는다.
3) visitor-case 매핑은 N1 고정 8건을 최우선하고 N2~N5 40건의 필수 스토리 슬롯을 보호. 랜덤 사건은 허용 조합만 배치.
4) 엔딩 30개에 실제 `ending_trigger_E##` 생성과 우선순위 정의. 진엔딩에는 PZ01~05 및 EV 필수 검증 플래그가 모두 필요. 모든 E01~E30 실제 도달 테스트를 넣는다.
5) 벡터 프로토타입 에셋으로 씬 충돌/터치 영역/보행 상태 검수. 출시용 아트는 별도 리소스로 교체.
6) 기존 테스트 및 100개 사건/30개 엔딩 상태 분기 자동 테스트. Windows/macOS/Linux에서 브라우저 경로 동작하도록 보정.

## 3. 릴리스 차단 조건
- 최종 캐릭터 아트와 모션 정합성 검증 전 출시 금지.
- 자동 생성된 이미지 한 장을 다수 리소스 완성 근거로 사용 금지.
- 미연결 엔딩 및 스토리 슬롯이 있으면 완료로 보고 금지.
- 실제 원본 소스·런타임을 비교하지 않은 상태에서 변경완료 보고 금지.
