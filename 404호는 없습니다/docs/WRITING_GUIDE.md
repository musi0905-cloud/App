# 404호는 없습니다 — 대사 다시 쓰기 지침

게임: 아파트 야간 경비원이 밤에 찾아온 방문객을 들여보낼지 정하는 한국어 추리 게임.
플레이어는 ① CCTV 보기 ② 주민·방문 기록 보기 ③ 집에 전화하기 ④ 한 번 더 확인하기를 한 뒤
"들여보내기" 또는 "문 열지 않기"를 고른다.

목표: **초등학교 고학년도 한 번 읽고 바로 이해할 수 있는 말**. 절대 어려우면 안 된다.

## 문장 규칙
1. 해요체만 쓴다. (예: 들어갔어요, 확인하세요). 경비원 대사도 해요체.
2. 한 문장에 한 가지 사실. 한 문장은 되도록 30자 이내, 최대 40자.
3. 누가 무엇을 했는지 분명히 쓴다. 주어를 빼서 헷갈리게 하지 않는다.
4. 쉬운 일상어만. 아래 말은 쓰지 않는다(괄호 안처럼 바꾼다):
   승인(허락), 대조(비교해 보기), 원본(관리실에 있는 기록), 세대(집), 등록 세대(그 집),
   신원(누구인지), 진위(진짜인지), 확정(확실히 알기), 표시 정보(화면에 나온 글자),
   제출(보여 준), 발급(새로 만들어 줌), 반송(돌려보냄), 인원(사람 수), 동일(같은),
   상이(다른), 해당(그), 미확인(아직 확인 못 함), 무단(허락 없이), 경유(거쳐서), 위조(가짜로 만든),
   불일치(서로 다름), 방문 대상(가려는 집), 연락처(전화번호).
5. 명사로 끝나는 메모체(예: "사람 확인", "보여 줌하고")를 쓰지 않는다. 모두 완전한 문장.
6. 조사·띄어쓰기를 정확히. "돌려보냄된", "보여 줌한" 같은 틀린 말은 반드시 고친다.
7. 시각은 "10분 전", "지금"처럼 상대적으로 쓴다. 숫자 시각(00:13 등)은 쓰지 않는다. 화면이 따로 보여 준다.
8. 느낌표, 영어, 한자, 줄임말을 쓰지 않는다. (CCTV는 그대로 쓴다.)
9. {name}(방문객 이름), {unit}(가려는 호수)은 그대로 써도 된다. 게임이 채운다. 중괄호 모양 그대로 둔다.

## 흐름 규칙 (가장 중요)
- 무엇이 이상한지 → 왜 이상한지 → 무엇을 더 확인할지, 이 순서로 이어지게 쓴다.
- **정답을 미리 말하지 않는다.** 아래 '보이는 때'를 지킨다.
- 사건의 뜻, 정답(safe), 핵심 단서가 있는 도구(channel)는 절대 바꾸지 않는다. 표현만 쉽게 바꾸고, 필요하면 구체적으로 풀어 쓴다.
- 들여보내도 되는 사건(safe=true)은 "처음엔 이상해 보이지만 확인하면 괜찮은 이유"가 분명해야 한다.
- 들여보내면 안 되는 사건(safe=false)은 "확인해도 풀리지 않는 이상한 점"이 분명해야 한다.

## 필드별 뜻과 보이는 때

| 필드 | 보이는 때 | 쓰는 법 |
|---|---|---|
| claim | 처음부터 (방문객이 인터폰에 하는 말) | 방문객의 자연스러운 한두 문장. 사건마다 조금씩 다르게. 이상한 점이나 정답을 말하지 않는다. role(방문 구분)과 맞게. |
| scenes[i].note | CCTV를 연 뒤 | 그 장면에 보이는 것 한 문장. 장면의 location/action/mode/prop와 맞게. 6자 이상. |
| document.field | 기록을 연 뒤 | 비교하는 항목 이름. 짧은 명사구 (예: "가려는 집", "택배 번호", "출입 카드"). |
| document.left | 기록을 연 뒤 | 방문객이 말하거나 보여 준 내용. 한 문장. |
| document.right | 기록을 연 뒤 | 관리실 기록에 적힌 내용. 한 문장. left와 달라야 한다. |
| document.source | 기록을 연 뒤 | 관리실 기록의 이름 (예: "관리실 방문 기록", "택배 보관 기록"). 짧게. |
| call.source | 전화를 연 뒤 | 어디로 전화했는지 (예: "관리실에 적힌 그 집 번호"). |
| call.state | 전화를 연 뒤 | 통화 상태 한마디 (예: "연결됐어요", "답을 기다려요", "말이 이상해요"). 짧게. |
| call.line | 전화를 연 뒤 | 통화에서 들은 내용 요약 한 문장. |
| call.detail | 전화를 연 뒤 | 경비원 메모 한 문장. 다음에 무엇을 볼지. |
| call.dialogue | 전화를 연 뒤 (**음성으로 읽힘**) | 첫 통화 대화 3~5줄. [{"who":..., "text":...}]. 첫 줄은 경비원. |
| call.verifySource | 한 번 더 확인할 때 | 다시 확인한 곳 (예: "다른 카메라와 그 집 주민"). |
| call.reply | 한 번 더 확인한 뒤 | plain.confirmed와 같은 문장으로 둔다. |
| call.verifyDialogue | 한 번 더 확인할 때 (**음성으로 읽힘**) | 확인 통화 2~4줄. 마지막 줄에서 plain.confirmed 내용이 드러난다. |
| plain.what | 핵심 도구를 확인한 뒤 | 무엇이 이상한지 1~2문장. |
| plain.check | 핵심 도구를 확인한 뒤 | 다음에 무엇을 확인할지 1문장. "~하세요"로 끝. |
| plain.confirmed | 한 번 더 확인한 뒤 | 확인해서 알게 된 사실 1~2문장. 판단 근거가 분명하게. |
| plain.decision | 결과 화면용 | safe=true면 "들여보내도 돼요.", false면 "문을 열어 주면 안 돼요."에 이유 한마디를 붙인다. 예: "문을 열어 주면 안 돼요. 먼저 들어간 사람이 아직 안에 있어요." |

### 통화 대사 규칙 (음성)
- who는 다음 중 하나만: "경비원", "주민", "관리실", "방문객", "가족", "회사 직원", "자동 응답", "모르는 사람".
- 소리 내어 읽기 좋게: 괄호, 기호(·, /, →), 숫자 나열을 넣지 않는다. 번호는 "일 층"처럼 쓰지 말고 그냥 "101호"처럼 써도 된다.
- 한 줄은 한두 문장. 실제 전화처럼 자연스럽게.
- 첫 통화(dialogue)는 핵심 단서가 전화(channel=통화)인 사건이면 그 이상한 점이 대화에 드러나야 한다. 그 외 사건에서는 결론 없이 "확인해 볼게요" 정도로 끝난다(정답 금지).
- 확인 통화(verifyDialogue)는 plain.confirmed의 내용을 대화로 보여 준다.

## 출력 형식
입력 파일의 각 사건에 대해 아래 JSON 객체를 만든다. **이 필드만** 넣는다. 다른 필드(id 제외)는 넣지 않는다.

```json
{
  "id": "A001",
  "claim": "...",
  "scenes": [{"note": "..."}, {"note": "..."}, {"note": "..."}],
  "document": {"field": "...", "left": "...", "right": "...", "source": "..."},
  "call": {"source": "...", "state": "...", "line": "...", "detail": "...", "verifySource": "...", "reply": "...",
           "dialogue": [{"who": "경비원", "text": "..."}],
           "verifyDialogue": [{"who": "경비원", "text": "..."}]},
  "plain": {"what": "...", "check": "...", "confirmed": "...", "decision": "..."}
}
```
- 입력의 document에 "claim" 키가 있으면 출력 document에도 "claim"을 넣는다(방문객이 한 말과 같게, 쉬운 말로).
- call.reply는 plain.confirmed와 글자까지 같게.
- 결과는 JSON 배열 하나로 파일에 저장한다. UTF-8, 한글 그대로(유니코드 이스케이프 금지).
