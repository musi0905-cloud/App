## 3. `CLAUDE_CODE_IMPLEMENT.md` 9개 지시 대응

1. **백업과 E01~E06 보존** — 엔진 `ending()`과 `VERSION '0.2.0'`을 바꾸지 않았다. 변경 전 상태는 커밋 `640db9a`. v1.2 JSON은 수정하지 않았다.
2. **스키마 변환, 원본 덮어쓰기 금지** — `room404/scripts/convert-gates-v13.py`가 v1.3 파일을 읽어 `dist/data/story_gates.json`을 만든다. 테스트가 변환 결과와 원본을 조건 단위로 대조한다.
3. **이야기 상태 필드** — `nightCompleted`, `completedScenes`, `evidenceAcquired`, `evidenceVerified`, `puzzlesSolved`, `sceneChoices`, `archiveEndingConfirmed`, `victimNamesPreserved`, `externalSubmission`, `finalChoice`, `selectedArchiveScene`을 저장한다. 모두 화면 행동 함수(`story.js`)에서만 바뀐다.
4. **E07~E27은 명시적 '이 기록으로 마무리'로만** — 보관함 근무 기록 탭에서 버튼을 눌러야 판정한다. 조건이 모자라면 스포일러 없는 힌트를 보여 주고, 근무는 그대로 이어진다.
5. **E28/E29/E30 최종 선택 분리** — 최종 증거보드의 세 버튼. E30 조건이 모자라면 제출 버튼이 꺼지고 자료·기록 대조·근무 기록 탭으로 가는 버튼을 보여 준다.
6. **판정 화면 비공개, 확정 플래그 즉시 리셋** — 2장 추가 기록 참고. `archiveEndingConfirmed`는 판정 직후 false로 돌아간다(테스트로 확인).
7. **증인 픽스처 테스트** — 30개 양성, 필드마다 1개 이상 변형 음성(총 203건), 5야간 실제 진행 시나리오.
8. **저장 이전과 안전 복구** — 2장 5번 참고. 소스는 배포·공개하지 않았다.
9. **검증 기록** — 이 보고서. 엔진 테스트, 실제 클릭, 저장→재실행, 실기기 각각을 PASS/SKIP로 나눠 적었다.

## 4. 문서로 정한 설계 판단

기획 문서가 직접 정하지 않은 부분은 v1.0~v1.3 문서에서 근거를 찾아 이렇게 정했다.

- **증거 입수 규칙** — v1.2 슬롯의 `acquire_rule: main_case_resolved_and_independent_check_done`에 따라, 판정을 마친 뒤 기록 카드의 '독립 자료 대조하기'를 눌러야 자료를 받는다. 놓친 자료는 그 야간이 끝난 뒤 보관함 '자료 복구'로 받는다(`miss_recovery`, v1.2 결정 8).
- **검증(확인됨) 규칙** — v1.3은 "어떻게 verified로 바꾸는지는 구현 테스트 필요"라고만 했다. v1.1 05번 증거 원장의 '교차 확인' 열을 써서, 대조할 자료를 하나 이상 입수한 뒤 보관함에서 '교차 확인하기'를 눌러야 확인된다. 다른 장면에서 같은 자료를 다시 받으면 독립 출처로 보고 확인된다(v1.1 장면표의 "EV05 검증", "EV16 검증" 등과 일치).
- **퍼즐** — v1.1 05번의 정의대로 각 퍼즐의 자료 3건을 작성 시각 순서로 놓는다. 입력 자료가 모두 확인돼야 열린다. 틀리면 다시 고를 수 있고 벌칙이 없다. 자료의 월·일·분은 02번 연표(2004-11-18 20:40 방문, 21:10 사망, 21:25 방화)에 맞춘 제작 값이다.
- **장면 처리 선택** — v1.3의 선택값 21개를 화면 문장으로 옮기고, 각 장면에 결말과 무관한 절차형 대안을 하나씩 더했다(대안 값은 문서에 없다). 선택은 판정과 별개이고, 고르기 전에는 다음으로 넘어가지 않는다.
- **피해자 이름 보존·외부 제출** — v1.3이 어떤 행동이 이 값을 바꾸는지 정하지 않았다. N5_07(서민아, "가족 이름까지 지울 수는 없어요")과 N5_08(원본 보관 기관 직원)의 처리 선택으로 바뀌게 했다. 놓쳐도 진엔딩이 막히지 않도록(v1.1 05번 "대체 경로 제공") 최종 증거보드에서도 기록할 수 있다.
- **저장 키** — v1.2 01번 예시대로 `404_story_v3`를 새로 쓰고 `404_active_v2`는 오늘의 근무에만 쓴다.

## 5. 해결되지 않은 모순 (숨기지 않음)

1. **E03·E04·E05의 `terminal: true`와 "야간 결과로 N2~N5 진행 잠금 금지"(v1.2 결정 6, v1.2 게이트 규칙)** — 두 규칙이 충돌한다. 1야간이 끝나면 해당 엔딩 컷신을 보여 주고, '2야간 근무 시작'은 그대로 열어 두었다. 이 엔딩에서 이야기를 끝낼지는 기획 결정이 필요하다.
2. **E07~E27의 `terminal: true`와 "메인 진행 상태를 지우지 않는 복제된 결말 리플레이"(v1.2 01번)** — 엔딩 화면으로 그 기록을 끝내되, 본 저장의 진행은 남겨 두고 근무를 계속할 수 있게 했다. 엔딩을 본 뒤 이야기를 강제로 끝내야 한다면 바꿔야 한다.
3. **장면 내용과 결말 선택의 의미 연결이 약한 곳** — 증거 번호는 21개 모두 맞지만, 장면에서 기록을 들고 온 사람의 말과 결말의 사건이 서로 다른 이야기인 경우가 많다. 예: N2_01 최미경 "제 이름이 새 명부에서 빠졌어요" ↔ E07 가짜 교대자, N2_03 강민수 "도면에는 창고인데…" ↔ E09 우산을 든 사람(외양만 보고 단정), N3_04 장혜숙 "그날 일은 부풀려졌어요" ↔ E17 봉쇄 계단 단독 진입, N4_05 회계 자료 보관자 ↔ E25 캠프 관계자의 전화, N4_06 선거 캠프 직원 ↔ E26 피해자 이름 기록. 선택 문장은 결말 쪽(v1.3 `narrative_causality`)에 맞췄다. 장면 대사나 결말 배치를 다시 맞춰야 한다. v1.3 문서도 "상투적 대사 검수 필요"라고 적었다.
4. **N5_03 증거** — v1.1 장면표는 "EV08 검증", v1.2 슬롯은 EV20. 더 새 문서인 v1.2를 따랐다.
5. **E01과 E06의 조건** — v1.1 표에서 둘 다 "1야간 완주"다. 기존 엔진대로 첫 근무는 E06, 오늘의 근무는 E01이다. 지시에 따라 엔진 판정은 바꾸지 않았다.
6. **E28·E29가 N5_01·N5_02 완료를 요구** — 5야간을 마치면 항상 참이라 실제 효과가 없다. 의도된 연결(예: 그 장면의 선택)이 있다면 기획이 필요하다.
7. **엔딩 데이터 품질(v1.1)** — 30개 모두 4컷·대사 3줄이 연결됐지만, 대사 화자가 세 종류로 고정돼 있다. 예를 들어 E30의 마지막 줄을 '교대자'가 말한다. 본문 `ending_text`는 E30만 다르고 나머지 29개가 같은 틀 문장이다. 4컷 연출의 완성도는 v1.3 문서도 미검증이라고 적었다.
8. **증거보드 형식** — v1.1 UI 명세는 사실/추정/반증 3탭이다. 이번에는 자료마다 '보여 주는 것'과 '보여 주지 못하는 것'만 나눴다.

- 긴급 신고 버튼(v1.1·v1.2 명세의 별도 행동)은 없다.
- N2~N5 판정 화면은 기존 사건 자료(방문객·이상징후)를 그대로 쓴다. 기록을 들고 온 사람의 그림·음성은 없다.
- 증거 원본 이미지와 상호작용 화면(도면 뷰어 등)은 없다. 자료는 글 카드다.
- 장면 대사 검수, 엔딩 4컷 연출 검수(5장 3·7번).
- 실기기(Android·iOS) 확인.
