# v0.19.0 게임 적용 보고 (2026-10-17)

확보한 이미지·애니메이션을 실제 게임 화면에 연결한 결과입니다. "파일 확보", "QA 뷰어 표시", "데이터 등록"은 게임 적용으로 세지 않았습니다. 아래 "게임 적용"은 실제 게임 화면(인터폰·CCTV·증거 화면)에 나오는 것만 셉니다.

배포, 공개 링크 생성, 공유 설정 변경, 기존 세이브 삭제는 하지 않았습니다. 이름·날짜·엔딩 같은 기획 내용도 바꾸지 않았습니다.

  - 그래서 CCTV가 덧그리던 역할 소품(`ROLE_PROP`)은 역할 그림에는 그리지 않습니다.
  - 단서 소품(장갑·우산 등 장면 소품)은 그대로 그립니다.

## 2. NPC06 전체 흐름 적용 여부

**적용했습니다.** 실제 방문객 화면(인터폰)에서 재생합니다(`tests/npc06-flow.mjs`, Chromium 모바일 에뮬레이션).

### 재생 흐름

- 처음 입장할 때 enter 0→47이 한 번 재생됩니다.
- 이어서 settle 0→15가 재생되고, idle이 반복됩니다.
  - idle은 24프레임 주기이고, 반복하는 구간은 idle 하나뿐입니다.
- 판정 뒤에는 turn 0→39 → start 0→14 → exit 0→47이 재생된 뒤 결과 화면이 나옵니다.
- 회전은 대기 23번 또는 47번 프레임 직후에만 시작합니다.
  - 이 두 프레임은 회전 첫 프레임과 맞도록 만들어진 프레임이며, 화소 차이로 측정해 확인했습니다.
- 입장 중에 판정해도 입장을 끊지 않습니다.

### 그리기

- 고정 720×1280 캔버스 좌표를 그대로 씁니다.
  - 프레임마다 다시 가운데 맞추지 않습니다. 알파 상자만 잘라 원래 위치(dx, dy)를 보존합니다.
- 배경과 같은 변환(×1.5, 인터폰 카메라)을 씁니다.
- 프레임 데이터의 접지 그림자를 그립니다.
- 소품(어깨 가방)은 정면·측면·후면 모두 같은 어깨에 있습니다. 좌우 반전 없음을 캡처로 확인했습니다.

### 판정과 저장

- 판정은 누른 즉시 저장됩니다.
- 같은 틱의 연속 클릭이 3번 들어와도 판정은 1건만 남았습니다.
- 퇴장 중에는 입력 버튼을 잠그고 "결과 바로 보기"를 줍니다.
- 감시 타이머가 있어서 화면이 그려지지 않는 상태(백그라운드)에서도 진행합니다.

### 모션 감소·로드 실패·파일 검사

- 모션 감소 설정: 대기 0번 프레임을 정지로 보여 주고, 판정하면 바로 결과로 갑니다. 저장 진행은 같습니다.
- 로드 실패: 페이지 404나 해시 불일치가 나면 NPC06 정지 그림이 대기하고 콘솔에 오류를 남깁니다. 사건은 계속 진행됩니다.
  - 퇴장 페이지만 실패하면 제자리에서 사라지고 결과로 갑니다.
- 다른 판·손상 파일: `clip.json`의 판 이름이나 PASS 표기를 바꾸면 재생을 거부합니다(해시 연쇄 검사).
- 재생 속도는 24fps입니다. 잠정 근거입니다.
  - 패키지에 속도 항목이 없습니다.
  - 비교 영상 `NPC06_v10r5_BG02_comparison.mp4`가 24fps(ffmpeg로 확인)입니다.

### 성능

- 시작할 때 263장을 디코드하지 않습니다.
- 그 방문객 차례에만 해당 페이지를 읽습니다(arrive·stay를 먼저, leave는 뒤에).
- 다음 방문객의 클립은 디코드하지 않고 캐시만 데웁니다.
- 방문객이 바뀌면 ImageBitmap을 닫고 타이머·RAF를 정리합니다.
- 페이지는 2048 이하 7장, 4.4 MB입니다. 알파는 무손실이고, 알파 가중 색 오차는 최대 1.83/255입니다.
