# 캐릭터 v4 보행 수정

## 적용 범위

방문객 01~08의 다가오는 보행 시트를 교체하고 공통 렌더러의 프레임 순서, 발 기준점, 이동 거리와 보행 주기의 관계, 장면별 명도·채도 및 접지 그림자를 수정한다. 옆걸음·뒷걸음·대기·제스처 원본은 기존 v2/v3 파일을 사용한다. 이 자료는 게임 연결용 파일이며 운영 중인 게임에 배포하지 않았다.

이번 재개 시 이전 임시 v4 파일 24개가 남아 있지 않아 해당 파일을 납품한 것으로 계산하지 않았다. 아래 실제 PNG 8개를 재제작했다. v3 원본은 보존한다.

## 파일 연결

`visitor-01/`~`visitor-08/` 폴더를 게임의 `dist/assets/characters-v4/` 아래 그대로 복사한다. 각 폴더에는 `visitor-0N-walk-toward.png`가 있다. PNG는 1536×1024 RGBA, 4열×2행, 한 칸 384×512이다. 왼쪽 위부터 시간순으로 재생한다. 포장 과정에서는 시트 전체에 같은 배율을 적용한다. 프레임별 키를 따로 늘이지 않는다.

`runtime/replay.js`는 다음 원본을 기준으로 한 전체 대체 파일이다.

- 저장소: musi0905-cloud/App
- 브랜치: claude/ecstatic-galileo-qeuh0f
- 기준 커밋: 7ebd3a0c45d74d44500916ba536c9690433150e8
- 대상: 404호는 없습니다/room404/dist/replay.js

같은 기준이면 전체 파일을 대체하거나 `replay-v4.patch`를 적용한다. 이후 변경된 저장소에서는 패치 내용을 병합해 최신 변경을 보존한다. `assets/v2/`의 배경·소품·기존 동작 파일은 계속 필요하다. v4 자산을 찾지 못하면 기존 v2로 복귀하므로 네트워크 탭에서 새 PNG가 실제 로드되는지 확인한다. 캐시가 남아 있다면 프로젝트의 서비스워커 캐시 버전을 갱신한다.

## 코드 변경

- 발 간격으로 프레임을 정렬하던 코드를 제거하고 원래 시간순을 유지한다.
- 보행 때 인물 전체를 위로 띄우던 보정을 제거한다. 발 기준은 셀의 (192,496)이다.
- 화면상 이동 거리와 인물 높이를 바탕으로 보행 주기를 계산한다. 같은 시간으로 되감으면 같은 프레임이 나온다.
- 장소별로 밝기와 채도를 맞춘다. 적외선 및 특수 모드는 별도 효과를 유지한다.
- 바닥 그림자를 부드러운 타원형으로 바꾼다.
- doorFar처럼 시작과 끝 바닥 높이가 같은 경로에서 0으로 나누던 오류를 수정한다.

## 확인한 사항과 한계

좌표·보행 주기·되감기 계산은 8명, 13개 위치, 8개 행동 및 모든 기존 모드에서 검사한다. `node runtime/runtime.test.mjs`로 재실행한다. 이 검사는 그림의 자연스러움을 판정하지 않는다.

생성형 스프라이트는 모션 캡처가 아니다. 좌우 발 교대와 카메라 시점은 수정했지만 중간 자세의 보폭, 무릎 높이, 팔의 연결에는 과장이 남아 있다. 특히 07번은 추가 수정 뒤에도 좌우 발 교대가 충분히 명확하지 않아 최종 보행 자산으로 합격 판정하지 않았다. 천장 카메라 전용 각도와 계단 발판별 접지는 별도의 방향별 자산이 필요하다. 기존 옆걸음·뒷걸음 자산까지 새로 제작한 것은 아니다. 전체 게임의 퍼즐·엔딩 테스트와 실제 휴대전화 배포 검증은 이 렌더러 자료 검증에 포함하지 않는다.
