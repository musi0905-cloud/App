# 0.10.0 — 이미지 v3: 진짜 두 번째 카메라, 앞모습·뒷모습 걷기, 동작

2026-09-30

GPT로 만든 이미지 v3(배경 6장, 방문객 4명 × 3장 = 12장, 모두 18장, 약 30MB)를 받아 게임에 넣었다. 원본은 `visual-v3/`에 그대로 보관하고, 게임에는 WebP로 줄여 넣었다(약 2.6MB).

## CCTV 카메라
- **모든 장소에 진짜 두 번째 카메라가 생겼다.** 전에는 공동현관만 실제 그림이고 나머지는 좌우 반전이었다. 이제 좌우 반전은 쓰지 않는다.

| 장소 | ② 다른 방향 |
|---|---|
| 공동현관 ↔ 현관 옆 카메라 | 서로 (기존) |
| 안쪽 복도 | 복도 반대편 |
| 엘리베이터 | 엘리베이터 앞 복도 |
| 계단 | 계단 아래쪽에서 올려다본 모습 |
| 주차장 | 주차장 반대편 |
| 집 현관문 | 복도 끝에서 본 현관문 |

- **③ 위에서** 카메라를 추가했다. 지금은 공동현관에만 있고, 다른 장소에서는 버튼이 숨겨진다.
- 반대편 카메라(복도 반대편, 주차장 반대편, 엘리베이터 앞, 복도 끝)에서는 들어오는 사람이 **카메라에서 멀어지는 방향**으로 걷는다. 뒷모습 걷기 그림을 쓴다.
- 엘리베이터 앞 카메라는 엘리베이터 안을 볼 수 없으므로, 안에 서 있는 장면에서는 사람을 그리지 않는다. 걸어 들어가는 장면만 보인다.
- 계단 아래쪽 카메라에서는 내려오는 사람이 카메라 쪽을 보며 내려온다.

## 캐릭터 그림
- 방문객 4명 모두 **앞모습 걷기(3/4 앞모습)**, **뒷모습 걷기**, **동작 모음**이 생겼다.
- 카메라 쪽으로 들어오는 장면(`enter`)은 이제 옆모습이 아니라 앞모습 걷기로 걷는다.
- 동작 모음(칸 순서: 손 흔들기 2, 문 두드리기 2, 전화 2, 뒤돌아보기 1, 서 있기 1)을 동작에 연결했다.
  - `wave`: 손 흔들기 두 칸을 번갈아
  - `knock`: 문 두드리기 두 칸을 번갈아
  - `phone`: 처음 0.9초는 휴대폰을 드는 칸, 이후 귀에 댄 칸. 이때는 휴대폰 소품을 따로 그리지 않는다.
  - `turn`: 장면 중간(30~70%)에 뒤돌아보는 칸
  - `wait` 등: 서 있는 칸. 초상용 옛 그림(`visitors.png`)은 초상, 등록 사진, 얼굴 확대에만 쓴다.
- 손 흔들기·문 두드리기에 쓰던 장갑 소품 애니메이션은 동작 그림이 없을 때만 쓴다.
- 새 그림 12장은 발 위치(496)와 머리 위치(26)가 기존 걷기 그림과 같아 보정 없이 같은 기준으로 그린다.

## 기타
- HUD의 카메라 이름에 새 카메라 이름을 넣었다(`VIEW_NAMES`).
- 서비스워커 `room404-v0.10.0`. 새 WebP 18장을 캐시 목록에 추가했다.
- 검사 추가: 모든 장소에 실제 두 번째 카메라가 있는지, 동작별 그림 칸과 방향(앞모습/뒷모습/옆모습)이 맞는지, 반대편 카메라에서 멀어지는지.
- 엔진·데이터 14/14, 브라우저 9/9, 전수 100/100 통과.
