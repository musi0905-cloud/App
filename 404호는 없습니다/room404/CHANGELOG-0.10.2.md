# 0.10.2 — 휴대폰 실기기 지적 사항 수정

2026-09-30

사용자가 웹 테스트 링크(휴대폰)에서 본 문제 5가지를 고쳤다.

## 1. CCTV 걷기가 부자연스러움
- **걷기 그림 순서**: 받은 걷기 시트 8칸은 걷는 순서대로 그려져 있지 않았다(예: 옆모습 0·2·4·6·7이 모두 큰 보폭, 5가 모음). 그대로 8fps로 돌리면 다리가 튀는 것처럼 보였다. 이제 시트를 읽을 때 칸마다 발 부분(아래 14%)의 좌우 폭을 재서 **모음 → 중간 → 최대 보폭 → 중간 → 모음** 순으로 자동 정렬한다(`measureCenters()` → `cycleOrder()`, `order[시트]`). 동작 시트(`gest`)는 정렬하지 않는다.
- **좌우 흔들림**: 칸마다 몸통 중심이 최대 20px씩 달라 걸을 때 좌우로 튀었다. 몸통(20~45% 줄) 중심을 재서 같은 축에 그린다(`centers[시트]`).
- **걸음 속도**: 8fps → 12fps(한 걸음 0.67초, 실제 걷기와 비슷). `walkPhase(cursor)`로 소수 위치도 계산한다.
- **몸의 오르내림(bob)**: 다리가 모일 때 키의 1.4%만큼 몸이 올라간다. 두 명 장면은 서로 반대 위상.
- **접근 속도**: 순수 1/거리 원근은 6초 중 앞 3초 동안 거의 움직이지 않다가 뒤에서 급히 다가와 부자연스러웠다. 원근 곡선과 직선 이동을 반반 섞어 **첫 1초부터 움직임이 보이고 가까울수록 빨라지는** 정도로 완화했다(`actorPlacement()`의 `path`).
- **밝기**: 인물이 밤 배경보다 훨씬 밝아 오려 붙인 것처럼 보였다. 기본 필터를 `saturate(.6) brightness(.8)`로 낮췄다.
- 배경 영상(03~08)과 정지 배경이 같은 구도인지 프레임을 뽑아 비교해 확인했다(일치).

## 2. 목소리가 안 나옴 / 4. 소리가 안 나옴
- iOS Safari 등은 **사용자 탭 안에서** 첫 음성·오디오를 시작해야만 이후 재생을 허용한다. 기존에는 벨 소리(1.1초) 뒤에 음성이 시작돼 탭 밖이었다.
- `voice.js` `primeVoice()`(무음 빈 발화), `sfx.js` `primeSound()`(AudioContext resume)를 만들고, `game.js` `primeAudio()`가 **통화/재확인 버튼과 판단 버튼을 누르는 순간** 동기적으로 부른다.
- 브라우저 검사의 가짜 `speechSynthesis`는 빈 발화를 세지 않도록 바꿨다.

## 3. 기록부가 밀어서 안 넘어감
- 휴대폰에서는 `pointerup` 전에 브라우저가 스크롤 제스처로 가로채 밀기가 끊겼다. `touchstart`/`touchend`(passive)로 직접 받고, `[data-book]{touch-action:pan-y}`로 가로 밀기를 게임이 갖는다. 마우스는 pointer 이벤트 그대로. 0.35초 안에 두 번 넘어가지 않게 했다.

## 5. 글씨가 검정이라 안 보임
- 테스트 링크(artifact 뷰어)가 페이지 앞에 `body{color:#141413}`을 끼워 넣어 본문 색을 덮었다. `style.css`의 `body`에 글자색(`#e6e9d9`)과 `color-scheme:dark`를 직접 적어 어떤 환경에서도 밝은 글씨가 나온다. 카메라 버튼은 좁은 화면에서 4개가 두 줄로 접히도록 `auto-fit` 격자로 바꿨다.

## 검사
- 엔진·데이터 14/14, 브라우저 9/9, 전수 100/100 통과. `all-cases`의 걷기 프레임 기대값은 12fps 기준(0.5초 → 6번 칸)으로 바꿨다.
- 캐시 이름 `room404-v0.10.2`.
