# 0.12.0 — 캐릭터 v4 보행 수정 적용

2026-10-06

Drive `캐릭터_v4_보행수정`(README, PROMPTS, 검수결과, asset-manifest, runtime/)을 받아 `character-v4/`에 원본 보관(SHA-256 8개 전부 일치)하고 적용했다.

## 받은 것
- 방문객 01~08의 **다가오기 걷기 시트 8장**을 실제 걷는 순서(왼발 접지 → 체중 이동 → 오른발 통과 → …)로 다시 만든 것. 1536×1024, 4×2칸, 발 기준 (192,496).
- `runtime/replay.js`와 `replay-v4.patch`: v0.11.0(7ebd3a0) 기준의 렌더러 수정안. 저장소는 그 뒤 v0.11.1(시계 분리)까지 바뀌어서 전체 교체 대신 **내용을 현재 코드에 병합**했다.
- 검수 문서의 한계: 07번은 좌우 발 교대가 아직 충분하지 않음. 옆·뒷모습 시트는 새로 만들지 않음.

## 적용 (replay.js)
- 새 시트를 WebP로 줄여 `assets/v2/visitor-0N-walk-toward.webp`를 교체했다(v3 원본은 `visual-v3/`에 그대로).
- **프레임 순서**: 앞모습(`toward`) 시트는 받은 순서 그대로 재생한다. v3의 옆·뒷모습 시트는 걷는 순서가 아니라서 v0.10.2의 발 폭 자동 정렬을 그대로 쓴다. 몸 오르내림(bob)도 자동 정렬 시트에만 남겼다(v4 시트는 그림 자체에 체중 이동이 있음).
- **걸음 주기 = 이동 거리**(`travelPhase()`): 화면에서 움직인 거리를 키로 나눠 걸음 수를 정한다. 다가오기·가로지르기·내려오기 모두 같은 규칙이라 발이 미끄러지지 않고, 같은 순간으로 되감으면 항상 같은 프레임이다. 공동현관 들어오기 6초에 약 6주기(초당 두 걸음).
- **장소별 밝기**(`actorFilter()`): 공동현관·복도·엘리베이터·계단·주차장·현관문별로 명도·채도를 맞추고 아주 약한 블러(0.18px)로 배경과 섞는다. 적외선·어두운 외투·흐린 카드 모드는 그대로. 소품에도 같은 필터를 건다.
- 접지 그림자를 부드러운 타원 그라데이션으로 바꿨다.
- `doorFar`처럼 시작·끝 바닥 높이가 같은 경로에서 0으로 나누던 것을 고쳤다.

## 검사
- 엔진·데이터 16/16: 8명 × 13곳 × 8동작 × 5모드 × 7시점에서 좌표가 유한하고 걸음 주기가 결정적인지, doorFar 회귀, 새 시트 존재를 추가 검사. 브라우저 9/9, 전수 100/100(걷기 프레임 기대값을 거리 기준 1→4로 바꾸고 되감기 결정성 검사 추가).
- 캐시 `room404-v0.12.0`.
